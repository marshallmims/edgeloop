The local app can follow a clock it does not own. HereSphere or DeoVR plays the video in the headset. VLC can play it on this computer instead. Which program you started decides whether the toys follow that clock.

The 2.0 window, npm run desktop, reads a headset clock. Follow headset shows the headset's file, time, and play or pause. Port 23554 is the usual one. The packet is the DeoVR remote packet: a 4 byte length, then JSON with the path, the duration, the current time, the playback speed, and the player state. Host a clock listens in that same format, so a tool that already follows DeoVR can follow a video playing here. The toys do not run on that clock yet. The player still uses its own video element. A folder pairs Movie.mp4 with Movie.funscript and with Movie.v0.funscript or Movie.vib.funscript. A network share can be smb://nas/videos. The password stays in this process. It is not written into the address you see.

The steps below are the earlier host, port 8787. That one does push the playhead into the page. The card is in the Player, under Player clock. Connect still needs a heart-rate monitor and a toy. The status line says the player only supplies the time.

A headset

  1. Start the local app and leave the window open. Run the local app.
  2. In HereSphere or DeoVR, turn on the timestamp server. Port 23554 is the usual one.
  3. On the Player clock card, leave the player on Headset. Type the headset address, such as 192.168.1.20, and the port. Press Connect.

The headset is the server. This app connects to it. Both speak the DeoVR remote protocol: a length, then a short JSON report of the playhead. The app asks once a second and pushes the time into the page about five times a second.

Nothing listening at that address means the timestamp server is off, or the address is wrong. The status line says so. The video can stay on the headset. The scripts stay in a folder on this computer.

VLC, instead of a headset

  1. In VLC, open Preferences, Show All, Interface, Main interfaces, and turn on Web.
  2. Under Interface, Main interfaces, Lua, set an HTTP password if you want one. Leave the password on the card empty when VLC has none.
  3. On the card, choose VLC. The address is usually 127.0.0.1 and the port is 8080. Press Connect.
  4. Play a file whose name matches a script in the folder.

The app asks VLC for its status about every 400 milliseconds, through VLC's web interface. A refused password, a web interface that is off, or a port other than the one VLC is using shows on the status line. The usual miss is the web interface still being off.

The folder

Type a folder path and apply it. The app walks that folder for videos and .funscript files. It skips names that start with a dot, and it skips node_modules, .git, $RECYCLE.BIN, and System Volume Information. It stops at 8000 files.

Matching is the file name, not the folder. Movie.mp4 on the headset pairs with Movie.funscript in the folder. Movie.v0.funscript is the secondary toy. Movie.vib.funscript is that same secondary channel under the older name. The comparison ignores case. If the video name has no script, the status says there is no script with that name in the folder.

The video itself is not copied onto this computer when the headset is playing it. The app reads the script text out of the folder and hands it to the page.

What this computer remembers

The headset address, the port, whether you last used Headset or VLC, the VLC password, and the folder path are written to app/app-state.json next to the program. A copy of the project keeps its own file. The VLC password is in that file, in the clear, on this computer. The website never sees it.

The next start reconnects to the last player and reopens the last folder, when that folder is still there.

Then start the session

The clock being connected does not start the toys. Connect a heart-rate monitor and a toy, then press Play, the same as on the 1.1.5 player. Beat sync, Funscript morphing, and the travel range are that player's settings. This app does not add a second set.
